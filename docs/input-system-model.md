# 入力系の形式モデル

この文書は、キーボードからの打鍵を文字列に対応付ける仕組み（以下「入力系」）を形式的に定義する。対象は emiel に限らず、IME、タイピングゲーム、キー入れ替えソフトを含む。

分類と具体例の解説は [input-system-classification.md](./input-system-classification.md) にある。この文書は定義と性質だけを扱う。

## 0. 記法

- 有限集合 $`X`$ に対し、$`X^*`$ は $`X`$ の有限列全体、$`X^+ = X^* \setminus \{\varepsilon\}`$、$`\varepsilon`$ は空列。
- $`|x|`$ は列の長さ、$`x \cdot y`$ は連接。
- $`x \sqsubseteq y`$ は「$`x`$ は $`y`$ の接頭辞」、$`x \sqsubset y`$ は「$`x`$ は $`y`$ の真の接頭辞」。
- $`x \sqsubseteq y`$ のとき、$`y = x \cdot z`$ となる $`z`$ を $`x^{-1} y`$ と書く。

## 1. キーとイベント

- $`K`$：キーの有限集合。
- イベント：$`\mathit{Ev} = \{\downarrow k,\ \uparrow k \mid k \in K\}`$。
- 時刻付きイベント列：$`x = ((a_1, t_1), \dots, (a_n, t_n))`$。ここで $`a_i \in \mathit{Ev}`$、$`t_1 \le \dots \le t_n`$ は実数。
- 押下状態：$`D_0 = \emptyset`$ とし、$`a_i = \downarrow k`$ なら $`D_i = D_{i-1} \cup \{k\}`$、$`a_i = \uparrow k`$ なら $`D_i = D_{i-1} \setminus \{k\}`$。
- $`x`$ が整合的であるとは、$`\downarrow k`$ が $`k \notin D_{i-1}`$ のときだけ、$`\uparrow k`$ が $`k \in D_{i-1}`$ のときだけ現れることをいう。以下、イベント列は整合的とする。

## 2. 打鍵と打鍵化

### 2.1 修飾条件

- 修飾条件は、空でないキー集合の有限列 $`m = (G_1, \dots, G_r)`$、$`G_j \subseteq K`$ である。
- 押下状態 $`D`$ が $`m`$ を満たす（$`D \models m`$）とは、すべての $`j`$ で $`D \cap G_j \neq \emptyset`$ であることをいう。
- 各 $`G_j`$ は「いずれかが押されていればよい」キーの集まり（例：左右の Shift）、列全体は「すべてのグループが押されていること」を表す。$`r = 0`$ の条件は常に満たされる。

### 2.2 打鍵

打鍵の集合 $`\Sigma`$ は、次の 2 種類の要素からなる有限集合である。

- 単打 $`\langle k \mid m \rangle`$：主キー $`k \in K`$ と修飾条件 $`m`$。
- 同時押し $`\langle S \mid m \rangle`$：キー集合 $`S \subseteq K`$、$`|S| \ge 2`$ と修飾条件 $`m`$。$`S`$ の順序は区別しない。

### 2.3 打鍵化

打鍵化 $`\beta`$ は、時刻付きイベント列に打鍵列の集合を対応させる写像 $`\beta : (\mathit{Ev} \times \mathbb{R})^* \to 2^{\Sigma^*}`$ である。1 つのイベント列が複数の打鍵列に読めてよい（どれを採るかは §5 の受理で決まる）。

打鍵化は、イベント列のどの情報を読むかで 4 段階に分ける。次の射影を考える。

- $`\pi_0(x)`$：$`\downarrow`$ イベントのキーだけを順に並べた列 $`(k_1, k_2, \dots)`$。
- $`\pi_1(x)`$：各 $`\downarrow k`$ について、キー $`k`$ とその直前の押下状態の組を順に並べた列 $`((k_1, D_{i_1 - 1}), \dots)`$。
- $`\pi_2(x)`$：時刻を落としたイベント列 $`(a_1, \dots, a_n)`$。
- $`\pi_3(x) = x`$。

$`\pi_0`$ は $`\pi_1`$ から、$`\pi_1`$ は $`\pi_2`$ から、$`\pi_2`$ は $`\pi_3`$ から計算できる。

定義（打鍵化の段階）：$`\beta`$ が $`\pi_j`$ を経由する（ある $`f`$ について $`\beta = f \circ \pi_j`$ と書ける）とき、$`\beta`$ は段階 $`B_j`$ に属する。

- $`B_0`$：押されたキーの順序だけを読む。
- $`B_1`$：押した時点で他に何が押されているかも読む（前置修飾）。
- $`B_2`$：キーを離した順序も読む（押下区間の重なりによる同時押し）。
- $`B_3`$：時刻を読む（時間の閾値による同時打鍵判定、タイムアウト）。

命題 2.1：$`B_0 \subseteq B_1 \subseteq B_2 \subseteq B_3`$。

証明：$`\pi_j`$ は $`\pi_{j+1}`$ の関数なので、$`\pi_j`$ を経由する $`\beta`$ は $`\pi_{j+1}`$ も経由する。□

段階は、その入力系が必要とする最小の $`j`$ で表す。$`B_0`$〜$`B_2`$ に属する打鍵化は、時刻を単調に付け替えても結果が変わらない。

## 3. 変換表

- $`\Gamma`$：出力記号の有限集合。かな、英字、あるいはキーイベントそのもの（キー入れ替えソフトの場合）でもよい。
- $`\Pi`$：仮想記号の有限集合。$`\Sigma \cap \Pi = \emptyset`$。仮想記号は打鍵としては現れず、持ち越しの中にだけ現れる。$`\Delta = \Sigma \cup \Pi`$ とおく。
- 変換表 $`E`$ は有限集合 $`E \subseteq \Delta^+ \times \Gamma^* \times \Delta^*`$ である。要素 $`e = (\mathit{in}_e, \mathit{out}_e, \mathit{nxt}_e)`$ をエントリと呼ぶ。
  - $`\mathit{in}_e`$：読み取る記号列
  - $`\mathit{out}_e`$：出力
  - $`\mathit{nxt}_e`$：確定後に次のエントリへ持ち越す記号列

## 4. 解釈

打鍵列 $`s \in \Sigma^*`$ を読む過程を、配置（残りの打鍵列 $`r \in \Sigma^*`$、持ち越し $`c \in \Delta^*`$）の遷移で定める。

定義（1 歩）：配置 $`(r, c)`$ からエントリ $`e`$ で配置 $`(r', \mathit{nxt}_e)`$ へ進める（$`(r, c) \xrightarrow{e} (r', \mathit{nxt}_e)`$）のは、次がすべて成り立つときである。

- $`c \sqsubseteq \mathit{in}_e`$（持ち越しはエントリの読み取り列の先頭として丸ごと使われる）
- $`u := c^{-1}\, \mathit{in}_e \in \Sigma^*`$（残りの部分はすべて打鍵）
- $`u \sqsubseteq r`$ かつ $`r' = u^{-1} r`$

$`u`$ をこの歩の区切りと呼ぶ。

定義（解釈）：$`s`$ の解釈とは、$`(s, \varepsilon) = (r_0, c_0) \xrightarrow{e_1} (r_1, c_1) \xrightarrow{e_2} \cdots \xrightarrow{e_n} (r_n, c_n) = (\varepsilon, \varepsilon)`$ となるエントリ列 $`p = (e_1, \dots, e_n)`$ である。その出力を $`\mathit{out}(p) = \mathit{out}_{e_1} \cdots \mathit{out}_{e_n}`$ とする。

区切りを $`u_1, \dots, u_n`$ とすると $`s = u_1 \cdots u_n`$ が成り立つ。最後の持ち越し $`c_n`$ が空であることを要求するので、持ち越しを残したまま終わる解釈はない。

## 5. 方針と受理

### 5.1 区切りの方針 σ

各エントリに区切りの方針 $`\sigma(e) \in \{D, T\}`$ を与える。$`D`$ は「装置が最長一致で区切る」、$`T`$ は「区切り方を目標文字列に委ねる」を表す。$`E_D = \{e \in E \mid \sigma(e) = D\}`$ とおく。

定義（最長一致条件）：解釈 $`p`$ が最長一致条件を満たすとは、$`\sigma(e_i) = D`$ であるすべての歩 $`i`$ について次が成り立つことをいう。ここで $`w_i = \mathit{in}_{e_i}`$ はその歩で読み取った列である。

- $`r_i \neq \varepsilon`$ のとき：$`r_i`$ の先頭の打鍵を $`a`$ として、$`w_i \cdot a \sqsubseteq \mathit{in}_f`$ となる $`f \in E_D`$ が存在しない。
- $`r_i = \varepsilon`$ のとき（末尾条件）：$`w_i \sqsubset \mathit{in}_f`$ となる $`f \in E_D`$ が存在しない。

1 つ目の条件は、「次の 1 打鍵を足すと、より長いエントリの読み取り列の先頭になってしまうところでは切らない」ことを表す。2 つ目は、「より長いエントリの途中で打鍵列が終わる形では確定しない」ことを表す。

### 5.2 読みの方針 ρ

入力系全体に読みの方針 $`\rho \in \{D, T\}`$ を与える。

- $`\rho = T`$：$`E`$ をそのまま使う。同じ読み取り列に複数の出力があってよく、どれを採るかは目標文字列が決める。
- $`\rho = D`$：$`E`$ に全順序を与え、読み取り列が等しいエントリのうち最初のものだけを残した $`E^\rho \subseteq E`$ を使う（表の順序で先勝ち）。

$`\rho = T`$ のときは $`E^\rho = E`$ とする。$`E^\rho`$ と $`E`$ に現れる読み取り列の集合は等しい。

### 5.3 入力系と受理

定義（入力系）：入力系は組 $`S = (\beta, E, \sigma, \rho)`$ である。

定義（許容される解釈）：打鍵列 $`s`$ の解釈 $`p`$ が $`S`$ で許容されるとは、$`p`$ が $`E^\rho`$ のエントリだけからなり、最長一致条件を満たすことをいう。

定義（受理）：目標文字列 $`w \in \Gamma^*`$ に対し、$`S`$ が受理するイベント列の集合を次で定める。

```math
\mathrm{Acc}_S(w) = \{\, x \mid \exists s \in \beta(x),\ \exists p \text{ は } s \text{ の許容される解釈},\ \mathit{out}(p) = w \,\}
```

打鍵列のレベルでは $`L_S(w) = \{\, s \mid \exists p \text{ は } s \text{ の許容される解釈},\ \mathit{out}(p) = w \,\}`$ と書く。

定義（決定的な入力系）：すべての打鍵列 $`s`$ について、$`s`$ の許容される解釈の出力がすべて等しいとき（許容される解釈がない場合を含む）、$`S`$ は決定的であるという。決定的な入力系は、打鍵列から出力への部分関数を定める。目標文字列を持たない装置（IME、キー入れ替えソフト）は、決定的な入力系として表す。

## 6. 変換表の段階

変換表を構文で 5 段階に分ける。各段階は前の段階の条件を 1 つずつ緩めたものである。

- $`C_0`$：$`\Pi = \emptyset`$。すべての $`e`$ で $`|\mathit{in}_e| = 1`$、$`\mathit{nxt}_e = \varepsilon`$、$`\mathit{out}_e \neq \varepsilon`$。
- $`C_1`$：$`\Pi = \emptyset`$。すべての $`e`$ で $`\mathit{nxt}_e = \varepsilon`$、$`\mathit{out}_e \neq \varepsilon`$。さらに読み取り列の集合が接頭符号（$`\mathit{in}_e \sqsubset \mathit{in}_f`$ となる組がない）。
- $`C_2`$：$`\Pi = \emptyset`$。すべての $`e`$ で $`\mathit{nxt}_e = \varepsilon`$、$`\mathit{out}_e \neq \varepsilon`$。
- $`C_3`$：$`\Pi = \emptyset`$。すべての $`e`$ で $`\mathit{out}_e \neq \varepsilon`$。
- $`C_4`$：制限なし。ただし次の進行条件を課す。
  - 進行条件：打鍵を読まず（$`u = \varepsilon`$）出力もしない（$`\mathit{out}_e = \varepsilon`$）歩だけで、同じ持ち越しに戻る列が存在しない。

構文上 $`C_0 \subseteq C_1 \subseteq C_2 \subseteq C_3 \subseteq C_4`$。

## 7. 性質

命題 7.1（有限性）：$`E \in C_3`$ ならば、どの入力系 $`S`$ でも $`L_S(w)`$ は有限集合で、すべての $`s \in L_S(w)`$ は $`|s| \le |w| \cdot \max_e |\mathit{in}_e|`$ を満たす。

証明：$`C_3`$ ではすべての歩が 1 記号以上出力するので、$`\mathit{out}(p) = w`$ となる解釈の歩数は $`|w|`$ 以下である。各歩の区切りの長さは $`\max_e |\mathit{in}_e|`$ 以下である。□

命題 7.2（有限状態性）：$`E \in C_4`$ ならば、$`L_S(w)`$ は正規言語である。$`L_S(w)`$ を受理する有限オートマトンは、状態を (出力済みの長さ $`0..|w|`$、持ち越し、最長一致条件の検査が済んでいない読み取り列の集合) の組として構成できる。

証明の概略：持ち越しは $`\{\varepsilon\} \cup \{\mathit{nxt}_e\}`$ の有限集合に属する。最長一致条件は各歩の読み取り列 $`w_i`$ と次の 1 打鍵だけで検査でき、$`w_i`$ は読み取り列の有限集合に属するので、未検査の $`w_i`$ の集合も有限個しかない。出力済みの長さは $`|w|`$ で抑えられる。したがって状態は有限で、遷移は表から直接定まる。□

$`\beta`$ が有限状態の変換器で与えられる場合（emiel の打鍵化はこれに当たる）は、合成によりイベント列のレベルの $`\mathrm{Acc}_S(w)`$ も有限状態で受理できる。

$`C_4`$ では $`L_S(w)`$ が無限になりうる。例：仮想記号 $`\Pi = \{あ, い, う, え, お\}`$ と、打鍵 $`a`$ に対する表 $`(a, \varepsilon, あ)`$、$`(あa, \varepsilon, い)`$、$`(いa, \varepsilon, う)`$、$`(うa, \varepsilon, え)`$、$`(えa, \varepsilon, お)`$、$`(おa, \varepsilon, あ)`$、$`(あ, あ, \varepsilon)`$ … $`(お, お, \varepsilon)`$ を考える（すべて $`\sigma = T`$）。このとき $`L_S(う) = aaa(aaaaa)^*`$ である。

系 7.3：$`C_3`$ と $`C_4`$ は、受理される言語の族として異なる。

証明：命題 7.1 より $`C_3`$ の $`L_S(w)`$ は常に有限だが、上の例の $`L_S(う)`$ は無限である。□

命題 7.4：$`C_0`$ と $`C_1`$ は、受理される言語の族として異なる。

証明：$`C_0`$ では各歩が 1 打鍵を読み 1 記号以上を出力するので、$`s \in L_S(w)`$ なら $`|s| \le |w|`$。$`C_1`$ の表 $`\{(ka, か, \varepsilon)\}`$ では $`ka \in L_S(か)`$ で、$`|ka| = 2 > 1`$。□

$`C_1`$ と $`C_2`$、$`C_2`$ と $`C_3`$ が言語の族として異なるかは、この文書では証明しない。例による説明は分類の文書にある。

命題 7.5（方針の包含）：$`\beta`$ と $`E`$ を固定すると、どの $`w`$ についても次が成り立つ。

- $`\mathrm{Acc}_{(D,D)}(w) \subseteq \mathrm{Acc}_{(D,T)}(w) \subseteq \mathrm{Acc}_{(T,T)}(w)`$
- $`\mathrm{Acc}_{(D,D)}(w) \subseteq \mathrm{Acc}_{(T,D)}(w) \subseteq \mathrm{Acc}_{(T,T)}(w)`$

ここで $`(\sigma_0, \rho)`$ は、すべてのエントリに $`\sigma(e) = \sigma_0`$ を与えた入力系を表す。

証明：$`E^\rho \subseteq E`$ なので、$`\rho = D`$ で許容される解釈は $`\rho = T`$ でも解釈である。最長一致条件は読み取り列の集合だけに依存し、$`E^\rho`$ と $`E`$ でその集合は等しいので、条件の成否は $`\rho`$ によらない。$`\sigma = T`$ は最長一致条件を課さないので、$`\sigma = D`$ で許容される解釈はすべて $`\sigma = T`$ でも許容される。□

命題 7.6（方針が効かない場合）：

- $`E \in C_1`$ ならば、許容される解釈は $`\sigma`$ の取り方によらない。
- $`E`$ の読み取り列がすべて相異なるならば、許容される解釈は $`\rho`$ の取り方によらない。

証明：$`C_1`$ では読み取り列の集合が接頭符号なので、$`w_i \sqsubset \mathit{in}_f`$ となる $`f`$ は存在せず、最長一致条件は常に成り立つ。読み取り列が相異なれば $`E^\rho = E`$ である。□

## 8. emiel の位置づけ

emiel は次の入力系として表せる。

- 打鍵化 $`\beta`$：$`B_2`$。押下状態と離した順序を使い、時刻は使わない（`StrokeCommitter`）。
- 変換表 $`E`$：`RulePrimitive.rawEntries`（プレフィックス展開の前のエントリ）。
  - $`\Gamma`$ はかなと英数記号、$`\Pi = \emptyset`$。
  - 持ち越しは打鍵だけで、次のエントリの読み取り列の真の接頭辞であることを要求する（`RuleEntry.isConnetableAfter`）。§4 の定義で、$`\mathit{nxt}_e \neq \varepsilon`$ の次の歩に $`u \neq \varepsilon`$ を課したものに当たる。
  - 出力が空でないことは前提としている（検査はしていない）。
  - よって $`E \in C_3`$。
- 区切りの方針 $`\sigma`$：エントリごとに `extendCommonPrefixCommonEntry` が true なら $`D`$、false なら $`T`$。
  - mozc 形式の読み込みでは、出力がレイアウトで直接打てる文字を含まないエントリが $`D`$ になる。
  - JSON 形式の読み込みでは、既定が $`T`$。
  - 直接入力ルール（`createDirectInputRule`）はすべて $`T`$。
- 読みの方針 $`\rho`$：$`T`$。
- 出力の比較：$`\mathit{out}(p) = w`$ の代わりに、正規化関数 $`\nu`$（既定は `defaultComposedNormalize`）を通して $`\nu(\mathit{out}(p)) = \nu(w)`$ で比べる。

実装と定義の関係について、次の 3 点は未検証または既知の差分である。

- 予想（プレフィックス展開の正しさ）：`expandPrefixRules` は、§5.1 の最長一致条件付きの表 $`E`$ を、最長一致条件なしで同じ $`L_S(w)`$ を与える表 $`E'`$ に変換する。トグル入力、「んa」、「あいabc」の例では一致を確認したが、一般の証明はない。
- `build` は命題 7.1 に基づき、$`L_S(w)`$ を DAG（`StrokeNode` のグラフ）として構成する。$`C_4`$ に拡張するには、命題 7.2 のとおり閉路を許すグラフが必要になる。
- `StrokeCommitter` は打鍵化 $`\beta`$ をオンラインで実装したもので、各時点で 1 つの読みに決める。そのため emiel が実際に受理する集合は $`\mathrm{Acc}_S(w)`$ の部分集合になりうる。たとえば、同時押しの候補しかない位置で片方のキーだけを押して離すと、打鍵は生成されずに無視される。

## 9. この定義の範囲外

次の性質は入力系の表現力とは独立しているので、このモデルでは扱わない。

- ミスの定義：受理されない打鍵のうち、どれを「ミス」として数えるか。emiel ではルール全体を参照して決める（otherMatched）。
- 判定の遅延：打鍵を受けてから受理・不受理を確定するまでに、どれだけ先のイベントを待ってよいか。
- 取り消し：Backspace による取り消しと、その統計上の扱い。
- かな漢字変換などの、出力後の変換。
